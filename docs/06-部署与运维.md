## 6.1 部署架构

```
┌─────────────────────────────────────────────────────────────┐
│                        部署流程                              │
└─────────────────────────────────────────────────────────────┘

  代码推送                 GitHub Actions              部署
      │                         │                       │
      ▼                         ▼                       ▼
┌──────────┐            ┌──────────────┐          ┌──────────┐
│   Git    │            │   构建测试    │          │  Pages   │
│  Push    │ ─────────> │              │ ──────> │  Deploy  │
│          │            │  npm run     │          │          │
│          │            │  build       │          │          │
└──────────┘            └──────────────┘          └──────────┘
                              │
                              │ 失败
                              ▼
                        ┌──────────────┐
                        │  通知管理员   │
                        │  (邮件/钉钉)  │
                        └──────────────┘
```

## 6.2 GitHub Actions 配置

```yaml
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
      
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 18
          cache: 'npm'
      
      - name: Setup Pages
        uses: actions/configure-pages@v4
      
      - name: Install dependencies
        run: npm ci
      
      - name: Build with VitePress
        run: npm run docs:build
      
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: docs/.vitepress/dist

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    needs: build
    runs-on: ubuntu-latest
    name: Deploy
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

## 6.3 点赞数据同步

```yaml
# .github/workflows/sync-likes.yml
name: Sync Likes

on:
  schedule:
    - cron: '0 * * * *'  # 每小时同步一次
  workflow_dispatch:

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 18
      
      - name: Sync likes data
        run: node scripts/sync-likes.js
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_KEY: ${{ secrets.SUPABASE_KEY }}
      
      - name: Commit changes
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add data/likes.json
          git diff --staged --quiet || git commit -m "chore: sync likes data"
          git push
```

## 6.4 部署检查清单

### 首次部署

- [ ] 创建 GitHub 仓库
- [ ] 配置 GitHub Pages（Settings → Pages → GitHub Actions）
- [ ] 设置 Supabase 项目
- [ ] 配置 Supabase 环境变量（Settings → Secrets）
- [ ] 启用 GitHub Discussions（用于 Giscus）
- [ ] 安装 Giscus App（https://github.com/apps/giscus）

### 环境变量

```bash
# Supabase 配置
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_KEY=your-service-key

# GitHub 配置（自动提供）
GITHUB_TOKEN=${{ secrets.GITHUB_TOKEN }}
```

## 6.5 自定义域名（可选）

### 绑定域名步骤

1. **购买域名**
   - 国内：阿里云、腾讯云（需备案）
   - 国外：Namecheap、Cloudflare（无需备案）

2. **配置 DNS**
   ```
   类型: CNAME
   名称: @ 或 www
   值: your-org.github.io
   ```

3. **添加 CNAME 文件**
   ```
   # docs/CNAME
   your-domain.com
   ```

4. **启用 HTTPS**
   - GitHub Pages 自动提供 SSL 证书
   - 等待 DNS 生效后自动启用

## 6.6 监控与维护

### 健康检查

| 检查项 | 频率 | 方式 |

## 6.7 故障处理

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 构建失败 | 代码错误、依赖问题 | 检查 Actions 日志 |
| 页面空白 | 路由配置错误 | 检查 VitePress 配置 |
| 点赞不更新 | API 错误、同步延迟 | 检查 Supabase 连接 |
| 评论不显示 | Giscus 配置错误 | 检查 Giscus 设置 |

## 6.8 回滚机制

### 手动回滚

```bash
# 查看历史版本
git log --oneline

# 回滚到指定版本
git revert <commit-hash>

# 推送触发重新部署
git push origin main
```

### 自动回滚

GitHub Actions 失败时自动回滚到上一个成功版本：

```yaml
# .github/workflows/deploy.yml
- name: Rollback on failure
  if: failure()
  run: |
    git revert HEAD
    git push
```
